# ADR 0004：显式开启的签名局域网发现

- 状态：已实现并通过本机 UDP 集成测试；跨 Windows 主机待验收
- 日期：2026-09-21

## 决策

用户在本机开启 LAN Web 发布时，Core 同时在 UDP `239.255.43.12:43112` 开启局域网组播发现；关闭 LAN 发布会停止发送和接收。每 5 秒发送一个不超过 4 KB 的 beacon，包括协议版本、Ed25519 公钥身份、时间戳、一次性 nonce、LAN 服务端口及不含工程内容的 Icepak 能力/负载摘要。整个 payload 由本机私钥签名。

接收端验证 Node ID 与公钥指纹、签名、字段上限、30 秒时间窗和 nonce 重放。未登记节点只显示为候选，不写入可信能力数据库；只有本机用户登记的公钥完全一致时，签名 heartbeat 才更新该节点的能力、新鲜度和负载。撤销信任后，即使仍能收到有效签名，也不再更新可信状态。发现记录只在内存保留 30 秒。

探测结果不能夸大 Icepak 能力：当前轻量探测只识别 AEDT/PyAEDT 的安装情况，多数 Windows 主机因此报告 `DETECTED` 且可用容量为 0。只有后续真实启动、许可证和工程验证证明 `READY` 时才允许进入自动调度候选。

## 安全与限制

- 组播报文是明文的，只包含节点公钥和能力元数据，绝不传工程路径、模型参数、Task、Artifact、配对码或 API token。
- 自签名只证明报文来自其声明的私钥；未知节点仍需用户核对指纹并登记，不能自动信任。
- 组播不是加密传输或双向连接。任务传输、远程求解和结果回传仍必须等待经过验证的双向握手及加密通道。
- UDP 组播可能被 Windows 防火墙、AP 隔离或 VLAN 阻断；服务只保证同一允许组播的局域网内尝试发现，不承诺跨网段可见。
- 两端时钟偏差超过 30 秒会拒绝 beacon，需要系统时间同步。
