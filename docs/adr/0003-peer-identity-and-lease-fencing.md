# ADR 0003：节点身份、信任登记与租约栅栏

- 状态：基础约束已实现；跨机协议未完成
- 日期：2026-09-21

## 决策

每个安装实例首次启动时生成 Ed25519 密钥对，私钥留在本机 App 数据目录，Node ID 是公钥 DER 的 SHA-256 前 128 位。Core 强制把新 Task 的 Owner 设为本机 Node ID，不接受浏览器或 DSH 提供的 Owner。旧版 `local-node` Task 在启动时逐条迁移并写审计事件。

数据库保存本机公钥指纹以锚定身份；私钥丢失或不匹配时不生成新身份接管已有数据库。备份和恢复必须保持 SQLite、Artifact 与 `identity/node-key.json` 同步。

其他节点必须在本机 App 由用户核对 Node ID、公钥后手动登记。此时状态仅为 `TRUSTED`，不等于已经建立双向连接或可执行任务。撤销信任立即使其活跃租约失效。未来网络握手必须以此公钥完成挑战签名验证，并在双向认证与加密通道内传输工程和结果。

Owner 只对 `QUEUED` Task 原子授予租约。租约包括随机 ID、递增 epoch、Executor、签发与到期时间；同一 Task 最多一个活跃租约。授予前要求可信节点最近 30 秒内报告 `READY`、匹配 AEDT 版本且负载未满。每次续租、接受进度或结果时，必须检查租约 ID、epoch、Executor、到期时间和 Task 当前 Executor。旧 epoch 的迟到结果不得覆盖现有 Attempt。

租约在传输/排队阶段过期时，Task 回到 `QUEUED`，可以重新调度；若已进入 `RUNNING`，Task 进入 `ESCALATED`，不会因网络分区自动启动第二次昂贵求解。Owner 重启后执行租约核对，并周期性处理过期或已撤销节点的租约。

## 尚未实现

- mDNS/UDP 自动发现与经过验证的双向配对。
- TLS/加密传输、签名心跳与远程挑战响应。
- 远程 Artifact 传输、Attempt 创建/回传及结果同步。
- 真实 Windows 双机断网、重连和迟到结果验收。

在上述能力完成前，手动登记不会触发远程调度；内存/SQLite 中的租约机制也不能被当作已经完成的组网功能。
