# ADR 0005：可信节点的双向签名身份握手

- 状态：本机集成测试通过；Windows 双机待验收
- 日期：2026-09-21

节点在本机手动登记并核对公钥后，才能发起身份验证。发起方对目标 Node ID、时间戳及 32 字节随机 nonce 签名；接收方先验证本机信任记录、公钥指纹、签名和 30 秒时间窗，再拒绝重复 nonce，并签名回传自身身份、发起方 Node ID 和原 nonce。发起方同样验证回包与本机信任记录。信任撤销后握手立即失败。

只有用户在本机“计算节点”页对当前 30 秒内发现的可信节点显式发起验证，Core 才向该节点广播的 LAN 端口发送 HTTP 请求。LAN Listener 对 `/api/peer/v1/challenge` 不要求浏览器 Cookie，但该路由只返回签名身份元数据且对请求体设 8 KB 上限。其他浏览器 API 仍受原配对会话保护。

该握手只证明双方持有已登记公钥对应的私钥；它不是 TLS，不阻止中间人转发，也不绑定后续连接。因此握手通过不会创建可传输 Task/Artifact 的会话，不会把节点标为可调度，不会自动派单。后续独立的加密 ping 通道见 ADR 0006；其 Task/Artifact 授权仍待实现。
