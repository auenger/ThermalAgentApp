本次核心变化

新增统一的 Harness 上下文入口。DSH 获取的不只是工具名称，还包括修改位置、代码约定、操作步骤，以及当前版本是否真正生效的依据。

四项新增能力

从分散说明，到可读取的操作约定
01 / 选择修改位置

先判断，改哪一层

区分工程参数调整、PyAEDT 兼容修复、依赖更新与宿主功能变化，避免用一种方式处理所有问题。

有明确的可修改范围。

02 / 理解代码约定

知道 Python 怎么写

提供 apply / verify 入口、参数类型、单位与范围、环境适用性及编写骨架；根据真实工程对象补全实现。

不再局限于 fan 通道参数。

03 / 管理执行与复用

跑过的方法，留下来

脚本按不可变版本 ID 保存，明确执行、查询结果、选用旧版本和再次复用的步骤。迭代计划包含参数边界与预算。

兼容性与成功记录随版本追踪。

04 / 读取实际状态

说明修改是否生效

实时读取更新策略、当前插件版本和候选状态；给出 App 中实际存在的应用入口，区分保存成功与运行生效。

用宿主状态支持结论。

一次工程调整如何进行

在有 Icepak 环境的机器上完成验证
STEP 01读取上下文

检查任务、AEDT 版本、真实对象和已有脚本。

STEP 02编写或复用

按参数约定保存新版本，或选择适用的已验证脚本。

STEP 03执行并读回

在任务工程副本执行，读取保存后重新打开的真实属性。

STEP 04留存与迭代

保存版本与产物；需要求解时准备有界计划，经 App 确认后运行。

脚本执行成功不等于仿真收敛或热设计达标，三个结果分别记录。新的 Python 方法通常无需重新打包整个 App。

延续上一轮引擎与安装包改进

如何升级与验证

旧 r2 安装包不包含本次 Harness 入口

1. 安装前：结束运行中的工程任务，完全退出 App，包括托盘进程；保留现有项目和数据备份。

2. 安装本轮包：运行下方 Windows x64 安装程序。本轮为普通 Thermal Agent，未生成 CAD Preview 专用安装包。

3. 检查上下文：打开 DSH 对话，输入：“先读取 App Harness，说明当前能修改哪些部分、Python 应怎样编写，以及插件修改后如何确认生效。”

4. 验证工程能力：在有环境的机器上选择一个已确认范围的非 fan 参数操作，检查脚本执行、工程读回、重启后的脚本复用和真实仿真结果。
