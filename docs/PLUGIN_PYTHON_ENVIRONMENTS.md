# 插件独立 Python 依赖

签名插件现在可携带离线 wheel 锁。宿主为每个包与基础环境组合创建独立的 venv，候选选择、验证、执行、回退及恢复旧作业都使用对应解释器。未声明依赖锁的旧插件继续使用 App 基础环境。

此功能要求 `hostApi: 2`，避免旧 App 忽略新字段并错误地在公共环境中执行。JSON-RPC 协议仍为 `1.0.0`；新宿主仍接受 API 1 的既有插件。

在 `plugin.json` 中添加以下字段，并将 wheel 放在 Python 源码目录下的 `wheels/`。填写真实版本和 wheel 文件 SHA-256：

```json
{
  "hostApi": 2,
  "pythonRuntime": {
    "schemaVersion": 1,
    "wheels": [
      {
        "name": "example-package",
        "version": "1.0.0",
        "path": "wheels/example_package-1.0.0-py3-none-any.whl",
        "sha256": "填写 wheel 文件的 64 位小写十六进制 SHA-256"
      }
    ]
  }
}
```

锁须包含完整依赖闭包；名称使用小写及连字符规范化形式。不能提供 URL、源码包、任意 pip 参数或安装脚本。沿用签名发布工具和发布者授权；DSH 不获得创建公钥或修改基础 Python 的能力。

安装步骤：

1. 校验已验签包、wheel 摘要及展开预算。
2. 在最终固定路径创建 venv 并用 Python 自带 ensurepip 离线初始化 pip。Windows 复制解释器，其他系统使用 venv 支持的链接方式。环境创建后不移动。
3. 使用 `--no-index --no-deps --require-hashes --only-binary=:all:` 安装指定 wheel，禁止源码构建；再运行 `pip check`，核对声明版本并采集实际依赖内容摘要。
4. 完成后才发布环境索引，随后仍必须通过宿主插件验证。报告的独立 PDF 读回、工程的内置参考插件使用基础环境，候选依赖不能替代参考验证器。

安装失败保留可用旧版本并清理此次尚未发布的环境，15 分钟后才重试同一包/基础环境组合；关闭自动更新或宿主会取消正在准备的进程。

缓存重用先由宿主扫描文件树，包括未列入 distribution RECORD 的额外文件、`.pth` 和字节码，不启动待检查的解释器。通过文件摘要比对后才运行 Python 环境采集，并再次核对文件树。目录链接不向外遍历；文件链接目标也参与摘要。这是协调时的采样检查，不是操作系统级不可变保证，也不消除检查与执行之间的竞争窗口。

文件缺失、改写或旧缓存尚无宿主文件清单时，自动更新开启的客户端会保留旧目录、隔离旧索引，从受信包的 wheel 锁重新创建环境。新环境产生新的执行身份，仍须通过对应插件验证才能恢复服务。若重建失败，则尝试其他可用受信版本；关闭自动更新时不重建。已持有租约的工作会使协调延后。旧格式索引迁移也走重建流程，不直接给旧文件补发可信清单。

重建记录持久化到 `python-environments/<key>.repair.json`，设置页展示准备中、准备完成或未完成及原因。准备完成不等于插件验证通过。当前最多展示最近载入的 20 条记录；被隔离的原环境不会原地覆盖，后续是否删除由下述保留规则决定。

包和环境身份同时保留在执行证据中。回退不会把旧依赖重新安装到新版本环境；已持有的租约继续使用原解释器。基础环境变化会使独立环境与参考验证器的绑定失效，需要重新准备和验证。

插件宿主通过 `host-owner.sqlite` 的长事务独占本地插件目录，在读取注册表前取得锁。同目录的第二个宿主会立即拒绝启动；默认 Core 在恢复作业前检查此归属。正常关闭会先取消准备和验证，再等待所有执行/固定版本租约释放，最后交出目录。即使调用方提前释放固定版本租约，已开始的 Python 调用也会继续持有底层租约直到结束。进程退出时由 SQLite/操作系统释放锁，不根据 PID 或超时猜测持有者是否存活。该数据库是锁载体，运行期间不可删除或替换。

独占保护不终止崩溃后可能残留的 Python/AEDT 进程，也不能约束忽略此锁的旧版 App 或直接操作目录的外部程序。插件目录应位于本地文件系统。

## 自动环境回收

默认 Core 在启动、定时及手动协调的空闲阶段执行清理；仅在自动更新开启、没有准备/验证/执行租约、没有未结束的 AEDT 操作时进入。维护期间新调用等待，关闭宿主也等待本轮清理结束。每轮最多删除两个超过七天的环境，避免一次集中清理大量依赖。

新环境在启动安装进程之前写入 `managed-environments/<env>.json`，记录包、缓存键、创建时间以及准备完成后的环境身份。安装、依赖检查、运行时采集、候选验证和业务执行都在启动 Python 前写入 `runtime-uses/<uuid>.json`，再登记子进程 PID，收到进程 close 后移除。Core 被强制终止时，存活子进程的记录继续阻止清理；只在系统明确报告 PID 不存在时移除残留记录。PID 复用或无权限检查会保守保留。启动与 PID 登记之间崩溃产生的未知启动记录也会保留，不根据超时猜测子进程已结束。

清理保留：

- 当前、上一版本和保持版本仍有索引的环境，以及当前解释器所在目录。
- 本地 Attempt、远程结果、readiness、建模作业当前身份文件和历史 Artifact 链接引用的环境，包括已完成作业，以支持后续重试/候选。读取身份文件时重新核对 SHA-256；证据缺失、损坏或超出采集预算时暂停整轮清理。
- 仍有存活或启动状态未核实的 Python 进程、尚在七天保留期内的环境。
- 旧版创建而没有受管归属记录的环境、未知目录和非普通目录。不会为它们补写可清理证明。

其他环境可自动删除，包括已无引用的旧版本、重建后隔离的旧副本、崩溃留下的有归属安装目录。先移除指向该目录的缓存索引并使内存快照失效，再删除目录；包代码、发布原件、验证记录和任务 Artifact 保留。删除中断时不会重新使用部分删除的环境，下次协调可继续清理。设置页的“依赖环境存储”显示最近一轮清理数量、保留原因和错误；该轮摘要不跨重启保存。

独立嵌入 `PluginHost` 的调用方必须注册完整的作业引用提供者，否则自动回收保持关闭。当前依赖 PID 的保守占用判断不负责终止孤儿进程；未知启动记录或旧环境可能仍需管理员核实。受信插件自行启动而未向宿主登记的脱离进程不在这一机制的覆盖范围；工程路径另由持久化 AEDT 操作门禁保护。这不是 OS 沙箱，也不提供任意断电时的目录持久化保证。

当前边界：

- 基础 Python 必须支持 `venv` 和离线 `ensurepip`；Windows 打包预检和 afterPack 会实际创建环境并运行 pip。仅能导入业务依赖的精简嵌入式 Python 不足以满足要求。
- 沿用签名包 32 MiB 内容、48 MiB 信封限制，wheel 展开合计限制 512 MiB；较大的 PyAEDT 依赖闭包还需后续独立资产传输。每个安装命令最多 120 秒，最多保留 64 个环境；达到上限且没有符合清理条件的环境时仍会拒绝创建，不牺牲在用环境或历史作业可复现性。
- 宿主文件树检查上限为 100000 项、1 GiB 和 60 秒，超限拒绝复用。索引控制元数据损坏或路径不合法时会拒绝使用，当前不自动推断其原归属。
- venv 隔离依赖目录，不隔离操作系统权限，也不提供完全独立的 Python 标准库/原生运行库。当前不下载或升级基础 Python 解释器。
- 已用真实 wheel、Python 子进程和真实 PDF 验证报告升级、重启、回退与失败回退。Windows/AEDT 的独立依赖升级仍需目标客户端验收；DSH 生成代码的执行隔离仍未完成。

实现依据：[pip 哈希与二进制安装约束](https://pip.pypa.io/en/stable/topics/secure-installs/)、[Python venv 的创建与不可迁移性](https://docs.python.org/3/library/venv.html)。
