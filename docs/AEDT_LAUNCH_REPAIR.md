# AEDT 启动路径自动适配

客户端有时已安装 AEDT，但缺少或保留了失效的 `ANSYSEM_ROOTnnn` 配置。宿主以前可以采集新版 `ANSYS Inc/vnnn/AnsysEM` 目录，却未把该路径交给插件进程，导致环境检查和实际启动使用不同的事实。

自动升级开启时，Core 现在从已有的 AEDT 文件清单生成插件进程专用的启动路径：

- 识别旧版 `ProgramFiles/AnsysEM/vnnn` 和新版 `ProgramFiles/ANSYS Inc/vnnn/AnsysEM`；主程序位于 `Win64` 时使用该子目录。
- 必须实际采集到 `ansysedt.exe` 才能成为路径候选。空目录不能补成有效配置。
- 已明确指向主程序所在目录的配置优先；缺失或失效的配置只在同一版本存在唯一候选路径时补齐。多个候选时显示诊断，不猜测路径。
- 学生版和 Python 客户端配置保留原类型，不转换成商业版；不自动安装 AEDT、修改注册表、用户/系统环境变量或许可配置。
- 自动升级关闭时不生成新的路径修复；已有任务继续使用其已捕获的启动环境。

PyAEDT 的版本解析器通过 `ANSYSEM_ROOTnnn` 等变量读取版本与安装路径，相关实现见 [官方 AedtVersions 源码](https://github.com/ansys/pyaedt/blob/main/src/ansys/aedt/core/internal/aedt_versions.py)。当前适配覆盖上述两类标准安装目录和宿主已经采集的 `ANSYSEM` 系列变量；尚未覆盖所有自定义路径、注册表安装源及 `AWP_ROOT` 配置路径。

## 与任务、验证及重启的关系

启动路径映射摘要作为 `aedt-launch-bindings` 加入环境身份。已有验证记录不能跨映射变化直接复用。独立 Python 环境也保留相同映射；实际业务调用、候选验证和内置参考插件使用对应的宿主快照。执行租约中的映射在任务期间保持不变，不重新读取后来改变的同名变量。

空闲后重新检查环境，后续任务采用新设置；App 重启后从实际安装情况重新构建映射，同一安装状态产生相同的适配结果。没有新增随系统配置漂移而失效的永久“修复成功”标志。设置页展示本轮补齐的变量、原路径、目标路径和歧义诊断。

映射只证明插件进程获得了宿主采集的路径，不证明主程序的发布者身份、AEDT 启动成功、许可证可用或工程求解兼容。现有启动和工程验证仍负责这些结论；文件采集本身不是操作系统不可变保证。

## 已验证范围

测试使用受控目录和非 AEDT 的占位文件验证新旧安装布局、失效变量、歧义处理和策略关闭。宿主集成测试运行真实 Python 子进程，检查路径注入、忙碌期间保持旧路径、空闲后使用显式新配置、重启后恢复自动适配，并确认没有修改父进程环境。独立 venv 测试检查路径映射和摘要的传递及缓存重用。

这些测试未启动真实 Windows AEDT。交付验收仍需在真实客户端确认“未设置安装变量 → App 自动补齐进程配置 → 启动及工程验证成功 → 重启后继续可用”。这项能力用于已知环境问题的直接修复；DSH 生成源码的隔离验证与自动启用仍是后续闭环的一部分。
