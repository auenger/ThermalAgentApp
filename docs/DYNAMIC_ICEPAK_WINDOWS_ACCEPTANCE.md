# 动态 Python / Icepak 实机验收

日期：2026-10-20。对应 [实施计划](DYNAMIC_ICEPAK_SCRIPT_PLAN.md)。

## 当前交付范围

本轮代码已接通动态脚本登记、任务工程副本执行、保存后重新打开读回、脚本复用、有界数值参数迭代、求解证据收集和任务界面。现有自动化测试主要使用工程接口替身；下列步骤必须在实际 Windows / Icepak 机器上完成，不能用本地测试数量替代。

需要：已安装并能正常求解的 AEDT/Icepak、可用许可、一个可测试的 `.aedt` 工程，以及 App 中配置好的模型。保留原工程，使用任务上传的副本。采用现有工程中真实存在的 setup、对象和参数，不根据本文猜测对象名称或 API。

安装器的覆盖安装和含空格路径问题仍未确认根因。本次动态脚本功能不等于安装器问题已经修复。若安装失败，记录完整报错、安装路径及旧版本名称。

## 1. 确认交付与环境

1. 根据试包同目录 `build-evidence.json` 和 `.exe.sha256` 核对源码提交与安装包摘要；版本号可能仍为 0.1.0，不能只凭文件名辨别。
2. 安装并启动 App，确认普通 AI 对话可用。
3. 在设置中检查环境和插件，确认实际 AEDT 版本与任务设置一致。可运行随包 `runtime-checks/accept-installed-runtime.mjs` 收集 Node、DSH、Python 运行时报告。
4. 创建本机任务，上传测试 `.aedt`，填写实际 AEDT 版本并确认计划。记录任务 ID。

## 2. 让 AI 生成一个非 fan 操作

先选一个实际工程支持、允许修改且容易读回的操作。例如修改指定对象材料、已存在的设计变量或明确的边界条件。测试对象和可改范围由工程负责人确定；不要把固定热源工况当作优化自由度。

可在对话中使用以下提示，并替换方括号：

> 对任务 [任务 ID]，先用 thermal_script_task_context 读取工程，再用 thermal_inspect_project 检查实际对象、属性和 setup。我要在允许范围内调整 [具体对象/参数与单位]，不使用固定 fan 通道接口。先查 thermal_script_library；若没有适用脚本，用 thermal_stage_script 生成参数化 Python。定义 apply(ipk, parameters) 和 verify(ipk, parameters)，verify 必须对保存并重新打开后的工程读回实际值。先解释将修改什么及范围，再在已确认的任务计划范围内执行。不要启动求解，不要使用虚构的对象或 API。保留脚本 ID 和执行 run ID。

验收记录：

- AI 是否读取实际工程并生成了 Python，而非仅在对话中粘贴代码。
- 脚本库是否出现对应版本和 DSH 提交来源。
- `apply` 和 `verify` 是否操作预期对象，读回值是否与用户参数一致。
- 任务记录是否成功，且 `executionKind` 为 `native-aedt`，没有替身标记。
- 原工程是否保持不变；工程副本中是否仅发生预期修改。

“读回通过”仅验证修改操作，不等于完成求解。工程副本不是任意 Python 的文件系统沙箱，脚本应在明确任务范围内工作。

## 3. 重启后直接复用

1. 完全退出 App，包括托盘，再打开。
2. 进入同一任务，在“可复用 Python 操作”中选择上一节的同一脚本版本。
3. 输入第二组不同且合法的参数，点击“在工程副本上执行”。不重新生成脚本、不重新打包 App。
4. 核对第二次工程读回与任务记录；记录两次参数、两个 run ID 和同一脚本 ID。
5. 可以在另一个具有匹配对象和环境的测试任务中再调用一次。若对象缺失或版本不匹配，应明确拒绝，不应沿用旧工程的成功结论。

## 4. 求解与多轮参数调整

1. 选择真正允许调整的连续数值参数或整数参数，明确上下限、初始步长、最小步长、温度目标、setup、最多轮数和总耗时。固定条件仍保持固定。
2. 可让 AI 用 `thermal_plan_script_iteration` 准备计划，或在任务页填写计划。
3. 检查页面显示的参数初值、范围和预算，点击“确认范围与预算并启动求解”。保存计划本身不应启动求解，DSH 不能自行调用 start 授权预算。
4. 观察每轮“调整参数 → 求解 → 结果”状态，核对实际 AEDT 求解是否运行。每轮从原始工程副本开始，避免累计修改干扰比较。
5. 检查每轮温度、收敛证据、最佳轮次与最终停止原因。目标达到和轮数/耗时耗尽必须分别显示；后两者不能报告为目标已达成。
6. 选取一次实际运行点击“停止自动迭代”，确认任务进入终态且相关受管进程完成退出后才开始下一次操作。

当前内置调参方式是有界坐标搜索；它以最高温度为目标，不保证全局最优。遇到脚本、环境或求解失败会保留证据并停止；AI 可以查询失败后提交新版脚本和新计划，不在进行中的迭代里偷偷换代码。

## 5. 导出与复核

在任务的脚本区域点击“校验并导出验收记录”，保存 `dynamic-icepak-<任务 ID>.json`。

导出包括脚本源码与定义、提交渠道及可用的会话 ID、运行/迭代记录、Core 实例标识、环境身份、产物摘要校验和 JSON 回执。原工程与求解工程等二进制仍在 App 产物库内，不内嵌进 JSON。如显示 `artifact-errors`，需先调查缺失或摘要不符的产物。

导出状态 `collected` 仅表示收集完成，`acceptance` 始终为 `manual-review-required`。DSH 提交通道不独立证明代码由模型生成；不同 Core 实例 ID 也不独立证明人工完全退出并重启 App。请同时保存对话和实机操作记录。
