# CAD 转换与 Baseline 建模设计计划

日期：2026-10-09；更新：2026-10-12

状态：实现中；本地流程与界面测试已通过，真实 Windows Icepak 与安装包验收尚未完成

目标：先把 CAD 转换能力集成到 App，再通过真实案例验证 CAD → Icepak 工程 → Baseline 的完整流程。

## 1. 目标与首版范围

用户上传 CAD，在 App 中填写材料、功率和环境等信息，系统生成 Icepak 工程，核对工程配置并检查网格，之后复用现有 Baseline 求解流程。生成工程和结果应可下载、可重复运行、可追溯到原始 CAD 与配置版本。

首版建议范围如下；自然对流是当前设计假设，实施前用实际案例确认其适用性。

| 项目 | 首版范围 |
|---|---|
| CAD 格式 | STEP / STP，单文件包含所需实体；其他现有上传格式仍可归档，但暂不宣称支持转换 |
| 执行环境 | 本机 Windows AEDT Icepak + 固定并经过验证的 PyAEDT 版本 |
| 求解场景 | 稳态自然对流，开放环境，明确的重力方向 |
| 对象 | 一个或多个实体热源、散热器及其他固体部件 |
| 材料 | 经测试的材料清单；每个参与计算的实体必须有明确材料 |
| 接触 | 经确认的直接接触采用理想接触；间隙保留，导热垫必须显式建模或留待扩展 |
| 监测 | 明确绑定对象的温度监测，显示监测方式和统计范围 |
| 操作 | 导入、配置、生成、验证、取消、重试、下载、启动 Baseline |

暂不覆盖任意复杂 CAD 自动修复、原生 CAD 装配依赖、PCB 详细层叠、热管/VC 等效模型、风扇曲线、瞬态和远程 CAD 建模。强制对流作为后续模板；实际首例若必须用强制对流，应先调整模板范围和验收配置。

## 2. 当前实现与待验收范围

- App 已接入 STEP/STP 导入、实体清单、配置表单、工程生成、持久化读回与网格验证、版本激活和 Baseline；其他 CAD 格式仍仅归档。
- Core、契约和 SQLite 保存导入身份、草稿、不可变建模版本、作业与产物；原 CAD 与求解输入分别归档。
- PyAEDT 插件已实现导入、热模型配置和验证适配；导入、建模、参数验证和求解共用持久执行锁与受管进程边界。
- Baseline 后的参数修改、结构/工况分类、读回验证和版本追溯已接入；该功能不自动恢复导入 CAD 的特征历史。
- 本地自动化与浏览器流程已有通过记录，2026-10-09 已生成包含 CAD 功能的 Windows 跨平台试包；真实 Windows 导入、网格、求解、安装与业务案例仍待验收。

### 2.1 Icepak、App 与 Agent 的职责

本期确定采用结构化表单与固定模板完成建模。CAD 转换与基础热模型生成不依赖 Agent、DSH 会话、模型 API 或网络服务；配置完整且本机 Icepak 环境可用时，用户可直接完成建模与求解。

| 层 | 职责 | 交付内容 |
|---|---|---|
| Icepak | 执行几何导入、材料与热边界设置、网格和数值求解 | 实际工程、网格、求解结果 |
| PyAEDT 插件 | 根据经过校验的配置调用 Icepak，读取实际状态，统一进度与错误 | 可重复执行的建模操作与验证证据 |
| App / Core | 提供对象映射与工况表单，维护模板、校验、版本、任务状态和文件身份 | 完整的 `ThermalModelSpec` 与可追溯执行流程 |
| 用户 / 工程师 | 提供材料、功率、环境等依据，确认关键映射与建模假设 | 已确认的配置与案例验收标准 |
| Agent（后续） | 从对话或资料整理配置草稿、推荐映射、解释错误和分析结果 | 带来源与待确认项的配置建议 |

“Icepak 有建模能力”意味着有执行接口；App 仍需明确调用顺序、对象对应关系和参数。仅导入 CAD 不会自动得到完整的热源、接触和环境配置。角色标签用于 App 引导，只有映射为实际材料、边界或监测设置后才产生仿真含义。

## 3. App 使用流程

1. **上传 CAD 并建立草稿**：沿用文件归档，显示文件名称、大小、SHA 和支持状态。
2. **导入并检查**：选择 AEDT 版本、声明/确认单位，启动后台导入。显示进度、实体列表、总尺寸、导入问题与模型截图。首版使用实体表格和截图，不以交互式 3D 预览作为交付前提。
3. **配置热模型**：逐实体选择角色、材料、是否参与计算；为热源填写总功率；设置环境温度、重力方向、计算域模板、监测对象及温度目标。
4. **查看建模摘要并生成**：展示全部对象映射、功率合计、材料、环境、接触假设及模板参数。点击生成后冻结本次配置，建立新版本。
5. **验证模型**：保存关闭并重新打开，读取工程实际值核对；执行网格检查，展示错误、警告和产物下载入口。
6. **运行 Baseline**：验证通过后允许用户启动求解。进入现有 Run/Attempt 流程，显示温度、收敛和热判定。

建模阶段不要求选择优化策略。CAD 建单入口应优先进入上述流程；原有 `.aedt` 上传路径继续可用。Baseline 后保留现有参数修改入口。

单位确认必须结合导入后的尺寸核对；导入接口的单位参数不能未经目标版本验证就视为所有 STEP 文件的缩放控制。单位/尺寸异常时停止后续建模。

## 4. 自动建模与对象映射

### 4.1 导入产物

返回实体名称、内部标识、类型、包围盒、体积（可获取时）、原有材料名称、装配关系（可获取时）和几何诊断。所有几何数值带单位。

对象引用使用本次导入产物内的稳定键，包含导入版本身份；配置同时保存名称及几何特征作为核对依据。重新导入产生新身份，不按相同名称自动沿用旧映射。面 ID 可能变化，涉及面的配置需在保存重开后重新核对其所属对象及几何特征。

导入空实体、非实体热源、异常尺寸或不支持格式时给出结构化错误。首版自动检查能力以目标 AEDT 实测为准，无法判定的接触关系显示待确认，不伪造已完成检查。

### 4.2 结构化配置

建议新增 `ThermalModelSpec`，至少包含：

- `schemaVersion`、源 CAD SHA、导入版本 ID、对象清单 SHA。
- 模板 ID/版本、AEDT/PyAEDT 版本、单位与方向。
- 对象配置：对象键、角色、参与计算状态、材料 ID/参数；排除对象须说明原因。
- 热源配置：对象键、总功率 W；首版不混用体热源与表面热源语义。
- 环境：温度 °C、重力向量、开放边界及计算域尺寸规则。
- 接触假设：已确认的接触对、理想接触或保留间隙；疑似关键间隙须处理后再生成。
- 监测配置：对象键、测量类型、数量及结果统计方式。
- 网格配置、求解配置和收敛标准；由版本化模板提供，可查看。
- 目标温度、记录人、说明、人工确认的假设。

自由文本需求保留为说明，不直接执行其中的数值。AI/名称规则将来可以建议映射；首版通过明确选择完成映射。

### 4.3 首个模板

模板名称建议为 `steady-natural-convection-v1`。生成过程依次创建/配置：固体材料、总功率热源、空气计算域、开放边界、环境温度、重力、监测点、全局与局部网格及稳态 Setup。

计算域间距、辐射是否启用、材料属性、网格与收敛阈值需要工程师为首个案例确定，并写入模板版本。不得把未经验证的统一默认值宣称为适合所有模型。导入修复选项也记录在版本中；首版不自动删除薄层、鳍片或关键间隙。

### 4.4 配置来源与后续 Agent 接入

首版配置记录区分 `USER_INPUT`（用户填写）、`CAD_METADATA`（CAD 导入元数据）和 `TEMPLATE_DEFAULT`（模板默认值），保存来源引用、单位及确认状态。CAD 中已有材料名称只能作为映射线索，需匹配可用材料定义并经过确认；模板默认项在建模摘要中明确展示。

为后续预留 `AGENT_PROPOSAL` 来源：Agent 只能生成配置草稿或建议修改，引用用户消息、资料或规则依据；未知材料、功率、环境和接触关系记录为待确认，不凭名称或外观自行补齐。置信度不能替代工程依据或必填校验。

Agent 草稿与手工表单使用同一 `ThermalModelSpec` 契约、对象目录和校验器。建议先进入可编辑草稿，用户核对后通过现有生成按钮冻结版本；后续接入无需另建一套建模执行器。Agent 不直接拼接 Python 脚本或绕过 Core 调用 Icepak。本期不新增 Agent 建模工具或自动修复循环。

模板与配置需区分可填写的工况字段、可选的已验证参数和模板固定字段。关键值或模板版本变化后创建新建模版本并重新验证，不能沿用旧验证证据。

## 5. 插件与 Core 接口

沿用 stdio JSON RPC、进度事件和受管进程。能力名称与方法名称分别登记，不与已有求解方法混淆。

| RPC 方法 | 输入 | 输出 |
|---|---|---|
| `inspect_cad` | 源 CAD 路径、源 SHA、输出目录、AEDT 版本、导入选项 | 导入工程、对象目录、尺寸、诊断、可用预览、环境版本 |
| `prepare_model` | 已归档导入工程及 SHA、对象目录 SHA、不可变建模配置、输出目录 | 生成工程、映射记录、配置应用日志、依赖清单 |
| `validate_model` | 生成工程及 SHA、期望配置、Design/Setup、输出目录 | 持久化读回结果、几何/边界检查、网格结果、错误和警告 |

建议新增 `cad.py`、`model_preparation.py`、`model_validation.py`。PyAEDT 调用集中在适配层，使用与现有测试相同的工厂注入方式；先在实际 Windows 版本验证接口行为再固定实现。

Core 新增 `ModelPreparationManager`，负责版本、后台作业、进度、取消、产物归档和恢复。HTTP 接口建议：

- `POST /api/tasks/:id/cad-inspections`：提交导入；返回作业 ID（202）。
- `GET /api/tasks/:id/model-preparations`：读取导入、草稿与建模版本。
- `PUT /api/tasks/:id/model-spec`：保存可编辑草稿，要求预期版本号。
- `POST /api/tasks/:id/model-preparations`：冻结草稿并生成工程。
- `POST /api/tasks/:id/model-preparations/:revisionId/validate`：验证并检查网格。
- `POST /api/tasks/:id/model-preparation-jobs/:jobId/cancel`：取消作业。
- `POST /api/tasks/:id/model-preparations/:revisionId/activate`：绑定验证通过的版本作为求解输入。

接口接收产物身份，由 Core 解析本机路径；不让前端指定任意源路径或输出路径。GET/下载按现有访问控制，修改沿用本机 Owner 规则。

导入、生成、网格、参数验证和求解共用一个持久可恢复的本机 Icepak 作业互斥边界；需审查所有启动入口，不能仅为新管理器添加一个独立 busy 标记。重复提交用请求身份幂等处理。

## 6. 版本、状态与产物

建议新增以下数据实体，具体迁移编号在实施时分配：

- `cad_inspections`：源身份、导入选项、状态、工程/对象目录/预览产物和诊断。
- `model_spec_drafts`：可编辑配置与乐观锁版本。
- `model_preparations`：不可变配置快照、revision、导入来源、模板版本、生成和验证产物。
- `model_preparation_jobs`：操作类型、状态、进度、时间、错误、取消和中断记录。
- `model_preparation_artifacts`：产物角色与 SHA 关联，不将生成工程冒充 `SOLVED_PROJECT`。

作业状态：`QUEUED → RUNNING → SUCCEEDED / FAILED / CANCELLED / INTERRUPTED`。

模型版本状态：`PREPARING → PREPARED → VALIDATING → VERIFIED`，生成或验证失败分别保存阶段错误；重试追加作业记录。修改配置创建新 revision，旧配置和证据不覆盖。草稿修改后页面明确显示“当前草稿尚未验证”，不把历史通过状态用于新配置。

Task 在建模期间保持 DRAFT，成功生成也不进入 RUNNING。验证通过且明确选择版本后，才允许确认成 READY；求解由现有 Baseline 作业驱动。App 重启将本机未完成建模作业标记 INTERRUPTED，不自动重复启动 AEDT。

工作目录：`workspace/tasks/<taskId>/model-preparations/<revisionId>/<jobId>/`，包含输入副本、生成工程、证据和日志。

源 CAD SHA 与求解工程 SHA 独立保存：任务输入绑定拆分成 `sourceModel` 和 `simulationInput`。生成工程通过后端激活，不通过改名或覆盖原 CAD 完成绑定。Baseline Attempt 的 `INPUT_PROJECT` 指向已验证生成工程，参数中记录建模 revision、配置 SHA 和验证证据 SHA。

工程保存后检查所需外部依赖。首版要求生成可独立重开的自包含输入工程；若依赖额外文件，则必须归档清单和文件并扩展暂存逻辑，否则拒绝标记 VERIFIED。不能假设归档一个 `.aedt` 就一定完整。网格检查在专用副本执行，记录与生成输入的身份关联；首版求解可重新生成网格，不承诺复用检查缓存。

## 7. 验证门槛与失败处理

模型 VERIFIED 至少要求：

1. 输入 SHA、配置 SHA、对象目录身份、模板与环境版本一致。
2. 在新的工程会话中读回正确的 Design/Setup、对象、材料、热源功率、边界、环境、重力及监测配置。
3. 所有参与计算实体有材料；所有热源绑定有效；功率有限且非负，合计大于零；导入单位和尺寸已确认。
4. 未解决的致命几何/关键接触问题为零；所有需要用户确认的假设已记录。
5. 网格生成成功，并达到首版模板定义的检查标准；保留能取得的网格统计与日志。无法取得必要证据时报告验证不完整。
6. 工程可从归档输入重新打开，不依赖导入作业的临时目录。

结构化错误区分环境不可用、CAD 导入失败、单位待确认、对象失效、配置不完整、读回不一致、依赖缺失、网格失败、超时、取消和中断，页面显示阶段与可修复项。失败产物保留但不可激活。

VERIFIED 表示模型准备检查通过，不表示求解许可证可用、结果收敛或温度达标。Baseline 继续分别记录执行状态、收敛、热判定和人工结果复核。

## 8. 实施里程碑

| 阶段 | 交付内容 | 验收出口 |
|---|---|---|
| M0：真实案例与接口验证 | 固定 Windows/AEDT/PyAEDT 环境；准备合法可使用 STEP；验证导入、保存重开、建模和网格调用；确定模板数值与监测方式 | 同一 STEP 能通过脚本创建并重开工程；形成环境记录和人工参考案例 |
| M1：App 内 CAD 转换 | 契约、导入插件、Core 后台作业、实体清单/截图、下载、取消/中断/重试 | 在 App 上传 STEP 后得到可打开的几何工程；页面明确“尚未配置热模型” |
| M2：基础热模型生成 | 对象映射表单、版本化自然对流模板、生成工程、读回验证和网格检查 | 从 App 配置生成可检查的完整工程；异常配置无法标记通过 |
| M3：Baseline 接入 | 源 CAD/求解工程身份分离、验证版本激活、现有求解流程接入、温度和证据展示 | 无需手动上传另一个 `.aedt`，即可从 CAD 完成 Baseline |
| M4：真实回归与安装包 | 成功/失败案例回归、工程人工核对、重复运行、Windows 安装包验证 | 验收记录和全部证据齐全，能够在安装后的 App 重复操作 |

按上述顺序开发，每阶段完成即测试。M1 是“CAD 转换已进 App”的首个可见成果；M3/M4 才是“CAD 跑出基础案例”的交付完成点。

M0 同时固定契约草案、模板参数与材料清单；M2 实现配置来源和待确认项展示。本期 M0–M4 均以无需 Agent 的完整流程验收。Agent 配置辅助作为后续独立阶段，在本期真实案例通过后接入。

| 案例 | 目的 | 预期 |
|---|---|---|
| 简单实体热源 + 散热器 STEP | 验证完整成功路径 | 材料/功率/边界正确，网格成功，Baseline 有收敛证据 |
| 多实体、多热源 STEP | 验证映射和功率合计 | 只对指定实体施加热源，名称相近对象不混淆 |
| 非法/损坏 STEP、无可用实体 | 验证导入失败 | 提示具体阶段，不产生可激活工程 |
| 尺寸异常/单位不明确 | 验证尺寸核对 | 要求明确处理后才能生成 |
| 关键间隙、薄层或重叠案例 | 验证几何与接触处理 | 保留问题证据，无可靠自动判断时明确待确认 |
| 映射过期/材料缺失 | 验证配置门槛 | 阻止生成或验证通过 |
| 网格失败或资源不足 | 验证失败恢复 | 无 VERIFIED 状态，可查看日志并重试 |
| 缺少求解许可证 | 区分建模和求解能力 | 建模状态保留，Baseline 明确失败原因 |
| 取消、App/Core 中断后重启 | 验证后台执行生命周期 | 无孤儿状态，进程回收、记录保留、明确可重试 |
| 从 Artifact 副本重新打开并求解 | 验证工程完整性 | 不依赖临时导入目录 |

人工参考工程使用相同 CAD、材料、工况、监测定义和求解设置。逐项核对建模配置，再比较温度和收敛；温度允许偏差、热量平衡及网格敏感性标准由首例工程师提前定义并记录，不在拿到结果后选择阈值。

当前 `metrics.py` 的 `tmaxC` 来自监测值中的最大值。首例必须验证所选监测方式能提供期望的温度统计；若不能覆盖对象最高温度，则新增对象表面/体域后处理指标。页面不得把点监测温度显示为全模型最高温度。

已新增 `assets/cad/reference-natural-convection.step` 及其生成、几何内核读回和 SHA 记录。它可用于简单参考案例，但尚未通过真实 Windows Icepak 验收；M0/M4 仍需要实际业务 STEP 与人工参考工程。客户样本未经授权不加入仓库。

## 10. 完成标准

- App 能从 STEP 直接建立基础工程，用户无需转去 Icepak 手动配置后再上传。
- 用户填写的信息可逐项对应到保存重开的工程实际设置。
- 原始 CAD、对象映射、模板、生成工程、验证和求解证据均有不可变身份关联。
- 错误、取消和中断留痕；配置或几何未完成时不能启动求解。
- 至少一个简单参考案例和一个实际业务案例在真实 Windows Icepak 上跑通，达到提前约定的工程验收标准。
- 安装后的 Windows App 能完成同一流程；本地替身测试通过单独报告。
- 用户无需使用 Agent 即可跑通完整案例；配置来源、模板默认项和待确认信息明确展示。

## 11. 后续推进顺序（2026-10-12）

以下为后续计划，不计入当前已实现功能；操作说明同步展示同一顺序。

| 阶段 | 工作与交付 | 验收出口 |
|---|---|---|
| P0：Windows Baseline 验收 | 使用公开 STEP 和一个业务 STEP，在安装后的 App 完成导入、配置、生成、验证、求解；保留版本、日志、工程与 SHA | 与相同工况的人工参考工程比较，满足提前约定的温度偏差、网格敏感性、热量平衡和收敛标准；完成取消/中断恢复回归 |
| P1：3D 对象选择与配置绑定 | 增加旋转、缩放、隐藏/隔离、实体树和选中高亮，联动现有配置表；显示网格与精确 STEP 分开管理 | 选中实体正确映射到 Icepak 对象；引用绑定源 SHA、导入版本和对象键，过期选择失效；查看器只读取已保存产物 |
| P2：几何预检查 | 检查实体有效性、拓扑、自相交、重叠和关键间距；先筛候选对再精确计算，记录单位、坐标、容差与排除项 | 已知接触/间隙/重叠/损坏样本得到正确证据；计算失败显示检查不完整；距离零不直接推断接触面积或热阻 |
| P3：参数化散热器模板 | 为鳍片数量、厚度、间距、高度、底板和包络建立受控模板；保存源模型和参数，每次修改生成新 STEP | 相同参数在容差内生成一致几何，非法参数被拒绝；新版本重新核对映射、材料、热源、接触与监测，在相同工况下比较 Baseline |
| P4：Agent 辅助对象改模 | 向 Agent 传递选中对象、产物版本、参数、约束及可选截图，输出结构化草稿与待确认项 | 修改落到正确对象；未知工程信息保留待确认，过期引用或非法参数被拦截；沿用 Core 校验与执行入口，手工表单仍可独立运行 |

新增几何组件先完成 Windows 打包和兼容验证，并与求解插件隔离。几何缓存可以重建，配置版本与求解审计记录持久保存。文件 SHA 用于身份核对，几何等价需按工程容差判断。

读取客户 STEP 不等于恢复原 CAD 参数或特征历史；几何优化需要参数模型或重建受控局部。任意复杂 CAD 自动参数化、通用多轮优化、强制对流、瞬态、详细 PCB 和热管/VC 等效模型需独立适配与验收。
