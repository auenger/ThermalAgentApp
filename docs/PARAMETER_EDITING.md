# Icepak 参数修改与追溯

更新日期：2026-10-12。

本次实现把手动参数候选扩展为一条通用流程：读取 Baseline 参数 → 编辑 → 保存新版本并验证 → 执行已验证工程 → 追踪求解结果。

CAD 输入须先完成 [建模与 Baseline 流程](./CAD_MODEL_PREPARATION_IMPLEMENTATION.md)，再使用本文的参数修改入口。现有适配器依赖已存在的参数或可修改字段；3D 选择、几何预检查和参数化散热器模板属于 [后续计划](./CAD_MODEL_PREPARATION_PLAN.md#11-后续推进顺序2026-10-12)。Windows 操作与测试记录也可使用 [离线 HTML 说明](./Thermal-Agent-功能进度与操作说明.html)。

## 使用方式

1. 完成 Baseline 求解并获得收敛证据。在 Task 页面顶部打开「参数修改与追溯」。旧任务可点击「重新读取参数」，从原 Baseline 工程副本补充参数目录，无需重复求解。
2. 搜索并添加参数，逐项填写目标值。数值保留当前单位，例如 `1.5mm`、`25W`。材料通过下拉列表选择。
3. 对未分类的模型变量，按模型实际含义选择「结构设计」或「工况条件」。填写记录人与修改原因。
4. 点击「保存新版本并验证」。后端生成不可覆盖的版本，复制工程、整批预检查、写入、保存、关闭并重新打开，再读取验证。验证不启动求解，可以离开页面。
5. 验证通过后执行该版本。结构候选沿用当前任务的单次 Candidate 规则（Baseline 为 FAIL 且未执行过 Candidate）；包含任何工况变更的方案创建关联新任务，单独求解 Baseline，不计算为结构优化收益。
6. 展开版本查看原值、目标值、持久化读回值、来源 Baseline、输入/验证工程及证据 SHA256、运行 ID。可比较版本、下载验证工程与验证证据、导出追溯 JSON，或复制历史方案为新版本。

未提交的编辑保存在此浏览器/桌面会话的 localStorage；提交版本保存在 Core SQLite，跨页面、重启后保留。记录人是用户填写的工程记录，不是已认证的身份签名。

## 首批适配器

| 适配器 | 支持范围 | 限制 |
|---|---|---|
| `variable` | 已有设计变量、`$` 项目变量 | 必须已被引用、非只读、当前表达式为数值常量；保留单位，不覆盖派生表达式；未知用途需要人工分类 |
| `material` | 指定实体对象材料替换 | 仅项目已加载的材料，排除空气/真空及材料库标记的气液材料；不会修改共享材料定义 |
| `boundary-power` | Block / SourceIcepak 的 `Total Power` | 当前值为 W / mW / kW 数值；只作为工况变更 |
| `fan` | 指定原生曲线风扇 | 转速比 >1 且 ≤1.5；按相似律调整 X/Y，未选择的风扇保持不变 |

几何调整要求模型已有驱动变量；本功能不会自动参数化导入 CAD。具体材料、边界及 AEDT 版本仍须在目标 Windows 环境确认。本次开发环境为 macOS，自动化测试使用独立仿真替身，不能代替真实 Icepak 验收。

## 工程与记录关系

- `parameter_plans` 表新增迁移 14。方案中的参数映射、原值、目标值、原因、用途、基准身份创建后不被更新；后续只追加生命周期状态与产物关联。
- 方案状态：`CHECKING → VERIFIED → STARTING → EXECUTED`；验证/启动失败为 `FAILED`。`EXECUTED` 仅表示已提交求解，求解成功、收敛及热判定分别读取 Run/Attempt/结果。
- 修改工程与验证 JSON 进入内容寻址 ArtifactStore。执行阶段直接使用已验证工程，不重复应用修改，避免风扇比例被重复累乘。求解前检查输入 SHA256、设计、Setup、AEDT 版本。
- 失败的验证记录保留请求和错误，不标记为已通过；求解失败仍可查看之前成功的修改验证证据。求解重试复用已验证输入工件，并继续关联原 Run。
- 启动中崩溃后，恢复逻辑寻找已创建 Run；若存在则恢复关联，否则明确标记中断。
- 工况子任务记录 `parentTaskId`、`parentBaselineAttemptId`、`parameterPlanId`，用户可双向跳转。原任务基准与审批状态保持独立。
- 旧 `fan_check` / `fan_solve` 协议及预授权风扇流程兼容保留；Task 页手动入口统一为参数方案。旧流程记录仍在 Run/Attempt 中，不伪造为新方案版本。

## 新增参数种类

1. 在 Python `parameters.py` 中增加发现、整批校验、写入及重新打开后的验证分支；只公开确定支持的字段。
2. 扩展 `IcepakEditableParameter.adapter` 和前端类型名称。已有适配器的新参数无需增加专用页面、求解流程或数据库表。
3. 添加真实含义约束（单位、范围、用途、目标对象）。新增类型必须验证失败时停止整批执行，不允许继续求解部分成功的方案。
4. 添加持久化读回、错误单位、失效对象、未选目标不变等测试，并在 Windows Icepak 上完成工程验收。

## 验证

- `pnpm test`：包含 Core/API/存储、Python 插件及现有报告测试。
- `node --test tests/parameter-plans.test.mjs`：修改版本、证据身份、独立工况、失败留痕、重复/过期请求、重试及重启恢复。
- `python3 -m unittest discover -s plugins/icepak-pyaedt/tests -v`：整批校验、保存重开后真实读回、风扇精确目标和异常处理。
- `PLAYWRIGHT_MODULE=<playwright-module-path> node scripts/smoke-parameter-workspace.mjs`：独立临时 Core 与仿真替身，检查编辑、本机草稿恢复、验证、版本比较、导出、窄屏和求解回链。默认尝试导入 `playwright`；不新增运行时依赖。

真实 Windows 验收应使用一个包含几何变量、固体材料和总功率边界的工程：验证只改目标参数、保存重开后值正确、求解运行在指定 Design/Setup、工况不会作为降温优化进行对比，并人工核对监测点与几何重建情况。
