# 客户端自主适配与插件升级

目标：App 在客户电脑识别环境或工程能力缺口，选择兼容插件；无现成适配时由 DSH 生成候选修复，在受管环境验证后按本机策略激活。失败时保留或恢复可用版本，正在运行的求解不中断，任务证据能追溯实际使用的代码与运行时。

## 当前进展

2026-10-19，分支 `feat/plugin-cache-lifecycle`，原始基线 `efddde3`，工程验证检查点 `c0b011c`。

已实现存储、适配和环境采集模块；业务执行已接入版本租约，Core 默认创建受管插件宿主：

- `ManagedPluginManifest`：独立于旧 Icepak `PluginManifest`，声明宿主 API、类型、Python 模块、能力、权限与精确的环境版本匹配。API 2 支持签名离线 wheel 锁，API 3 支持绑定大小和 SHA-256 的外部大型 wheel，继续兼容无依赖锁的 API 1 插件。
- `PluginStore`：导入目录中的 `plugin.json` 与文件，按 SHA-256 存储完整版本；拒绝符号链接、特殊文件、Windows 不安全路径及同版本不同字节。清单和代码共同参与包摘要。
- 安装只登记候选。验证记录绑定包摘要和完整环境摘要，激活要求相同环境下的验证通过及宿主允许的权限。验证回调只能由宿主实现，不能接受 Agent 自报“通过”。
- 单 Core 写入者使用完整包目录加原子 registry 替换。中断留下的暂存目录不参与执行，完整孤儿包经摘要复核可以重新登记。已有包保留用于回退。
- 执行租约阻止验证和切换影响正在运行的插件调用；每次执行前重新检查包完整性及环境证据。
- `PluginAdaptationController`：在宿主提供的可信包集合中选择最高兼容正式版本；验证失败的版本在相同环境下隔离，继续尝试较旧可用版本。权限增加、预发布版本和不可信包不自动启用。
- Icepak、Report 客户端可以注入受管运行环境获取函数；旧调用方保持现有启动行为。Python 使用 `-I -B`，避免向内容寻址的包目录写入字节码。报告超时等待进程关闭后才释放租约。
- 本地 Baseline、候选和重试锁定作业级版本，Attempt 中记录实际插件身份，不再硬编码 `0.2.0`。受管版本记录包摘要与环境摘要；旧记录不能伪装成有内容身份的受管版本。
- CAD 导入、生成、验证与 Baseline 通过 `PLUGIN_RUNTIME` Artifact 追溯并延续前一步身份；参数验证、参数候选和新工况基准延续基准身份。远程求解在结果中记录执行端身份，恢复回传时不再使用当前插件版本冒充求解时版本。
- `inspectPythonRuntime` 使用真正的隔离 Python 子进程读取解释器版本、ABI、标准库及安装依赖内容摘要，包含安装依赖的闭包；同版本文件变更也会改变环境身份。返回路径保留 venv 入口，不把符号链接解析成系统 Python 后丢失 venv 依赖。
- 受管报告客户端的宿主身份会作为 LOG Artifact 归档并绑定生成 PDF 的 SHA-256；报告代码自报的身份不会覆盖宿主租约身份。
- `PluginHost` 注册 App 内置插件，首次调用采集真实 Python 环境并验证启动协议；CLI 在启动时及每五分钟协调一次，忙碌时推迟。更新策略与回退保持状态持久化，重启后恢复。
- 本机设置页提供状态、环境诊断、自动更新开关、立即检查、回退和恢复更新；管理接口限制 loopback，写入校验 Origin。DSH 可调用 `thermal_plugin_status` 和 `thermal_reconcile_plugins`，诊断及协调宿主已信任的版本。
- 新增 Ed25519 签名离线包、发布者插件范围校验、设置页导入及 DSH `thermal_install_plugin_release`。签名原件持久保存并在协调时重验；报告更新通过独立 PDF 样例读回后才进入激活。签名 Icepak 更新默认仅登记，配置工程验证后限定能力包可进入验证与激活。发布工具及部署格式见 [PLUGIN_RELEASES.md](PLUGIN_RELEASES.md)。
- Icepak `0.2.1` 引入参数适配器注册表；Core 与界面按插件声明的 Schema 校验和编辑数值/枚举参数。新适配器可携带名称、版本、范围、默认值与提示，保留批量预检和保存重开读回。协议和限制见 [PARAMETER_ADAPTERS.md](PARAMETER_ADAPTERS.md)。
- 启动和定时协调已支持管理员配置的 HTTPS 更新目录：有界下载、同源地址、验签、缓存重验、取消与失败重试等待；先就绪本地插件，再获取更新。报告更新已验证自动发现到 PDF 验证和激活的流程，断网重启保留可用版本。

- 宿主工程验证已实现参数发现、工程副本修改、内置参考插件独立读回和双求解比较，复用持久化 AEDT 操作锁。签名包集成测试覆盖未授权仅登记、激活后实际调用、租约期间不切换、失败隔离、重启、配置变化重新验证和 AEDT 文件变化回退。设置页可展开查看验证检查与包/环境摘要。范围与限制见 [ENGINEERING_PLUGIN_VALIDATION.md](ENGINEERING_PLUGIN_VALIDATION.md)。
- 受管探测结果的身份由宿主租约覆盖，插件自报 READY 不授予可求解资格。本地及远程执行端 readiness 保存实际包/环境身份；复用前匹配摘要、校验结果文件 SHA-256 与求解成功字段。旧数据库增加可空身份列，历史证据不能认证受管版本。切换版本或环境后，节点心跳不再复用旧插件探测缓存。
- 远程任务完成时，Owner 将已验证 SHA-256 的结果文件中的插件身份写入 Attempt 与完成事件，和状态变更处于同一事务。拒绝错误插件 ID、不完整或无效摘要，不使用完成请求附带的身份。旧版结果缺少身份时移除派发阶段的运行摘要，版本字段仍保留历史派发值，不将其认定为实际执行证明；不回填既有已完成记录，也不以远程结果认证 Owner 本机 readiness。
- 宿主 RPC 解码发现缺失响应、非法 JSON、错误请求 ID、无效状态或响应字段时，持久化撤销实际包和环境对应的验证记录，并使当前 readiness 失效。已有租约继续持有版本，最后一个租约释放后自动重新选择已信任且验证通过的版本，不重试失败的业务调用。相同环境下的失败记录跨重启保留；新环境需要重新验证。正常业务错误（包括插件自报错误码）、超时和取消不触发此类隔离；自动更新关闭或回退固定时不擅自切换到其他版本。
- 运行时准备或适配失败后，后续调用及 DSH 协调遵守 30 秒起、最多 5 分钟的指数重试间隔；状态提供连续失败次数、原因和下次允许检查的时间。新签名版本登记、更新源补齐资产、实际策略变化会提前重新检查，同一包重复导入和相同策略写入不会绕过等待。成功后清除等待；进程重启会重新进行一次检查。等待不创建通过证据，也不重复业务操作。
- 显式回退不再依赖当前坏版本的健康检查：独立采集环境并核对目标旧版本的内容、信任和既有验证记录。自动更新关闭时也能恢复被隔离或损坏的当前包，但旧版本不匹配当前环境时拒绝切换；任务占用和准备过程中的目标变化仍阻止回退。
- Windows 环境摘要现在包含宿主采集的 AEDT 安装根目录及其直接目录、`Win64` 目录下的 EXE/DLL/PYD 内容。覆盖环境变量、旧版 AnsysEM 和新版 ANSYS Inc 默认目录；不依赖是否配置工程验证。安装文件增删或同版本改写会使旧运行身份与 readiness 失效。设置页提供安装路径和采集文件数。
- 独立 Python 依赖环境已接入候选协调、执行和回退；报告已通过真实离线 wheel 与 PDF 的升级/重启/跨环境回退测试。独立环境的权限、体积、基础解释器与 Windows 验收限制见 [PLUGIN_PYTHON_ENVIRONMENTS.md](PLUGIN_PYTHON_ENVIRONMENTS.md)。
- 独立环境损坏可在自动更新开启时从受信 wheel 锁重建，原目录保持用于诊断；先由宿主检查文件树再启动缓存解释器，检测额外 `.pth`、字节码和文件缺失。新环境重新取得插件验证记录，空间不足等失败保留可用旧版本；设置页可查看持久化重建记录。
- 新建独立环境已接入受管归属、启动前进程记录及空闲回收。保留当前/回退索引、存活或身份不明的子进程、本地/远程及建模历史引用；超过七天且无引用的环境每轮最多清理两个。未知旧环境不自动删除，损坏证据阻止清理。宿主与进程崩溃测试覆盖残留 Python 占用，尚不证明 Windows/AEDT 实机行为。
- 大型依赖现在可由签名清单声明，通过配置源同源 HTTPS 流式下载、按内容缓存，再交由离线 pip 安装。真实 TLS 测试覆盖超过 32 MiB 的测试 wheel、签名包登记后补齐资产、断网重建和 PDF 输出；仍需完整 Windows PyAEDT 依赖闭包、生产站点与 Windows 资产缓存回收验收。

这些机制不等同于已交付客户端自主升级。现阶段工程测试的“适配”使用真实 Python 子进程、注入环境事实和明确标记的替身协议，不证明任何 AEDT 版本兼容。

## 后续必须完成的闭环

1. **Core 装配与本机设置**：默认宿主、内置包注册、本机策略和回退已接入；仍需打包后的 Windows 客户端验收，以及更完整的验证证据展示。
2. **真实环境与依赖身份**：Python 内容与 AEDT 直接原生运行文件采集已接入。wheel 锁和大型外部资产可创建、重建独立依赖环境；插件目录已加入跨进程独占、关闭时的租约排空及带进程/作业保留规则的环境回收。资产缓存已接入版本和历史引用保留及空闲回收；仍需旧环境和未知启动记录的恢复流程、基础解释器升级和 Windows 工程验收。摘要是采样证据，不是 OS 级不可变保证。
3. **业务级版本锁定**：本地求解、建模、参数验证及远程执行已接入作业级租约与身份，受管报告身份已归档；readiness 已关联包与采集到的环境摘要。远程 Owner 接收结果时已从校验过的结果文件原子同步 Attempt 版本和运行身份；仍需所有 AEDT 安装的完整身份采集，以及升级后端到端业务验收。
4. **Host 验证器**：按能力执行环境探测、固定样例、参数发现、工程副本修改及保存重开读回；涉及求解行为的变化需要真实求解证据。协议 health 通过不能自动授予工程执行能力。复用现有 AEDT 操作锁与进程回收机制。
5. **可扩展参数适配器**：注册协议和数值/枚举 Schema 已接入；仍需真实 AEDT 扩展样例、数组/曲线等复杂类型，以及跨插件版本工程兼容性验证。保留单位、物理语义、对象身份和工况边界。
6. **可信分发与安装入口**：签名离线包、按插件 ID 限定发布者、HTTPS 更新目录、大型 wheel 缓存、导入入口和报告验证已接入；仍需生产发布站点、Windows 独立依赖部署验收及更强的系统配置边界。宿主决定可信集合，Agent 不得自签自授信。新权限走本机明确策略，不靠提示词约束。
7. **DSH 修复闭环**：已接入源码/证据读取与独立候选存档工具，参见 [PLUGIN_REPAIR_CANDIDATES.md](PLUGIN_REPAIR_CANDIDATES.md)。候选保留基础权限、能力和依赖锁，不进入可执行 Registry；已加入 Windows Sandbox 固定边界预检脚本（见 [WINDOWS_PLUGIN_ISOLATION_PREFLIGHT.md](WINDOWS_PLUGIN_ISOLATION_PREFLIGHT.md)），当前 Mac 只验证不支持路径，驱动替身测试不证明 Windows 隔离。下一步需目标 Windows 验收、完整资源边界与本机授权来源，再接入候选验证和升级请求。Python `-I` 不是系统沙箱。
8. **客户端定时协调**：启动、环境变化、能力失败与更新目录变化触发适配，空闲后重试，避免对同一错误无限修复。协议损坏已触发持久化隔离和空闲回退，并使旧工程 readiness 失效；仍需业务能力失败的分类诊断与有界修复触发。
9. **验收**：真实 Windows 客户端完成“发现失败 → DSH 修复 → 副本验证 → 空闲激活 → 后续任务成功”；验证运行中不切换、断电恢复、环境变化、旧任务复现，以及错误修复不能得到工程通过结论。

## 当前实现约束

- 默认宿主使用 SQLite 长事务实现插件目录跨进程独占；直接操作底层 Registry 的工具仍须遵守单写入者约定。尚未实现目录 fsync 的断电耐久保证，不应宣称具备任意断电恢复能力。
- 校验摘要用于发现内容变化，不代表发布者身份或 OS 沙箱。相同用户权限的恶意进程不在该文件存储层的防护范围。
- 真实依赖采集器已接入默认宿主，按五分钟窗口缓存；并非每次调用重新哈希，也不是运行期间的依赖隔离。AEDT 清单上限为 64 个根目录、5000 个文件、4 GiB 和 60 秒，读取失败或超限会阻止本轮环境认证。它不递归覆盖 AEDT 全部组件、外部动态库或操作系统组件，不修改或安装依赖。原生清单的真实 Windows 性能与覆盖范围仍需验收。
- 回退只切换代码版本，不撤销已发生的外部操作；工程修改必须继续使用副本，数据库迁移由宿主管理。
- 新 `plugin.json` 随 Python 源码打包，与旧清单并存。当前可执行来源为 App 自带代码、已配置发布者的报告更新，以及显式配置工程验证后的限定能力工程更新；启动协议检查不证明新的工程适配器或 AEDT 版本可用。完整 CAD/风扇更新仍待对应能力验证器。
