# App 内置 Harness 操作上下文

新增 `thermal_app_harness(taskId?)`，通过经过认证的 Core Bridge `GET /v1/harness` 读取宿主约定。普通助手在新增动态 Python、修改兼容插件或优化 App 前先读取；已知任务时同时读取真实任务上下文。

返回内容：

- `guide`：问题分类、可修改边界、工具调用顺序、Python 入口及参数格式、必须补全的脚本骨架、复用与版本选择、插件修复流程和实际应用入口。
- `availability`：当前是否存在动态脚本服务、托管插件宿主。
- `runtime`：当前策略、运行时、实际生效版本、候选应用状态；每次请求重新读取。
- `task`：可选的本机任务工程、AEDT 版本、确认状态、运行记录和脚本约定。其他节点的任务不会返回。

脚本保存会生成不可变 scriptId，按该 ID 执行，不存在额外的插件激活步骤。复用时须检查当前环境下的验证记录；修改逻辑保存新版本。插件修复则通过现有修复候选流程，应用入口为“设置 → 插件与自适应升级 → 修复候选 → 验证并应用此修复”，以宿主实际版本及状态判断生效。

受限修复会话仍只开放原来的三个工具；`thermal_plugin_repair_context` 返回相同的修复说明 `harness`。没有扩大修复权限，也没有新增启动求解或任意改写安装目录的能力。

DSH 引擎更新、宿主升级与 Python 修复明确分开，不把尚未实现的自主引擎升级描述成可用能力。脚本骨架未实现时会抛错，不用固定成功结果冒充工程读回。

本次修改 Core Bridge 和 DSH 适配插件，需要同时发布对应版本。此前 Windows r2 安装包不包含本次新增上下文入口。

验证：TypeScript 编译通过；动态脚本 API、插件宿主和 DSH 运行时共 41 项测试通过。真实 DSH 注册检查为普通预设 33 个工具、其中 24 个 Thermal 工具；受限修复预设仍严格为 3 个工具。
