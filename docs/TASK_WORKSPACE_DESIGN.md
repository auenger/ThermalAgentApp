# Task 工作台设计与当前边界

参考 `/Users/ryan/mycode/silieco/packages/views/issues/components/issue-detail.tsx` 的信息组织：Issue 正文承载长期上下文，属性栏承载当前状态，活动流承载人和 Agent 的推进，执行记录独立保留。Thermal Agent 沿用这一关系，不复制其代码或视觉组件。

## Task 的信息层次

1. **需求输入**：任务名称、详细散热目标、客户/项目、产品与工况、温度目标、监测点、可调整范围、模型文件。CAD 可以先形成草稿；`.aedt` 通过能力检查后才能求解。
2. **AI / 规则初筛**：按需求保存候选优化策略及命中依据。当前实现是关键词初筛，明确标记未经过 Baseline 验证，不冒充物理诊断。
3. **人工决策**：保存选定策略、确认状态、额外约束和风扇动作的单独授权。策略命中不等于模型中存在可执行目标。
4. **Icepak 执行**：每个 Run / Attempt 保留求解状态、最高温度、收敛状态和证据 Artifact；结果回到同一 Task，而不是离开 Task 形成孤立的“结果页”。
5. **持续推进**：状态事件和署名人工补充形成追加式时间线。记录本身不启动求解，人工确认和许可证占用边界保持不变。

## 页面入口

- 首页只给摘要、最近任务和“新建任务”入口，不内嵌完整表单。
- “任务”页负责查找和进入详情，不在表格行中塞入所有求解按钮。
- 独立建单页负责需求与模型录入、能力检查、候选策略选择和首次确认。
- Task 详情是后续工作主页面：结构化需求、能力、建议、确认、运行证据与时间线按稳定顺序呈现；右侧只放当前状态与下一步动作。

## App / Task / DSH 工作目录（2026-09-22）

- 默认 App 运行数据根目录由 Desktop 的用户数据目录或开发模式 `THERMAL_AGENT_HOME` 决定；App 工作空间固定为 `<home>/workspace`。DSH 会话 `cwd` 就是这个目录，DSH 的 Profile、会话日志和原始附件仓库仍在 `<home>/dsh`，不把配置数据混成工作文件。设置页只读展示工作空间，DSH 工作空间列表启动时收敛到 App 选定目录；散热建单工具拒绝其他 `cwd` 的会话。当前不提供在线迁移 App 根目录的 UI，迁移时应停 App 后整体备份/移动数据。
- 每个 Task 的工作目录为 `<home>/workspace/tasks/<taskId>`，其中 `inputs/` 保留任务输入副本，`runs/` 保留本机与远程求解过程，`reports/` 保留任务报告。Artifact Store `<home>/artifacts` 继续充当全局内容寻址、去重和证据源；Task 输入副本不改写上传原件。
- 表单建单 / 修改草稿时，把已上传模型复制到当前 Task 的 `inputs/<sha256>/<filename>`，`projectPath` 或 `cadSourcePath` 指向这份副本。旧任务在启动、列表或详情访问时补齐工作目录，但不会自动移动历史运行记录或改写历史路径。
- DSH 对话使用 `thermal_create_task` 建单时，取当前会话最近一次含文件的用户消息（允许中间有纯文本澄清）；Bridge 依据 DSH 附件引用的哈希、名称、长度在受控附件仓库校验原始字节，再复制至 Task 目录并记录 `conversationAttachments`。只有恰好一个 `.aedt` / CAD 模型附件时才自动绑定模型；多个模型保留全部附件，等待人工选择，不擅自指定求解对象。模型能力检查和人工确认 Gate 不变。更早的附件组、DSH 自行生成的文件及未上传的文件不会隐式归档。同一会话重复建单时应留意会复用最近一次附件组。

## 尚未闭环的部分

- 当前只有经过工程副本验证的曲线型原生 Fan `+10%` 是可自动执行的候选动作；其他五类策略仍需对象映射和各自的动作插件。
- “AI 建议”目前只是策略关键词初筛；要达到基于 Baseline 热分布的诊断，需要读取可审计结果指标，生成带证据引用的诊断版本。
- 通用多轮优化应在同一 Task 下新增“方案版本 → 人工批准 → 参数候选 Run → 对比 → 再决策”链路。当前追加记录和已有风扇候选可延续任务，但不能宣称已实现任意策略的自动二次改模。
- 人工补充的记录人由用户填写，尚未接入身份认证或电子签核，不能当作已验证专家身份。
