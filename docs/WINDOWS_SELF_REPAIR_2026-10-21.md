## 实测结论与正式修复

日志证明修复副本在 Windows / AEDT 2024.2 / PyAEDT 1.6.0 上完成启动和工程读取，未证明真实求解或动态脚本迭代完成。当前正式修复与日志副本不同，仍需 Windows 回归。

1. 受管请求在启动监视线程前预加载 PyAEDT，仅作用于 Windows 工程请求。健康检查与环境发现保持轻量；导入失败明确返回，不在包初始化中静默忽略。预加载的普通输出转入 stderr，进度事件仍保持 JSON 协议。
2. FILETIME 先以整数减去纪元偏移，再转秒；与 psutil 时间比较只允许 4 个浮点 ULP 的差异，拒绝毫秒级差异和非有限数值。不采用日志候选中的 1 秒容差。
3. 返回的工程版本统一为 `2024.2` 等语义版本，避免日志中实际出现的 `ANSYSEM_ROOT242` 与宿主验证条件不匹配。
4. 探测能力清单补齐 `dynamic_script`；插件正式版本提升至 0.3.1。

## DSH 诊断增强

Core 保留最后一个进度阶段。卡在 `pyaedt_preloading` 的超时产生 `PYAEDT_IMPORT_TIMEOUT`，按当前包和环境写入故障证据，供自动修复任务消费。普通求解超时仍按超时处理，不能据此认定为导入兼容错误。

修复上下文提供真实应用入口、自动应用策略、工程验证是否配置，以及自身优化的范围。DSH 提示词要求区分实测、推测和未验证部分；查询实际应用状态，不把候选存档描述为修复生效，也不凭空指引按钮。

## 候选从存档到应用

新增本机 App 的“验证并应用此修复”入口，以及独立的“候选通过宿主验证后自动应用”开关。自动生成候选和自动应用是分别配置的策略；应用不直接重放失败的客户任务。

应用检查当前基础包、环境、版本、文件摘要、继承的 manifest 和工程占用情况。只接受更新的稳定版本，不扩张原插件的权限、入口或依赖契约。登记后进入现有宿主验证与选择流程；失败记录保留，失败候选不会作为可用版本切换。已登记失败候选不会自动无限重试；需修订为新版本。

Icepak 修复继续要求配置 Windows 工程样例、摘要、允许的参数变化和求解预算，复用宿主的工程读回及参考/候选求解比较。界面可导入工程验证 JSON，具体字段见 [工程验证配置](ENGINEERING_PLUGIN_VALIDATION.md)。导入含 `allowValidationSolves: true` 的配置以及开启应用策略意味着允许执行该配置限定的验证求解。

此处是本机用户授予候选进入宿主验证流程的许可，不是发行者签名发布；签名更新源保持原机制。工程样例回归不证明所有 CAD、风扇、动态脚本或未来工程操作都正确，也不提供任意 Python 的操作系统级沙箱。
