01

打开工作台，确认状态

桌面应用启动后进入“概览”。浏览器诊断可在本机启动 Core 后访问工作台，但托盘和桌面生命周期需要用 Electron 验证。

02

配置模型后，用对话推进工作

在桌面 App 的“设置 → DSH 原生设置”配置模型与 API 密钥，然后打开“Agent”对话。Agent 会调用应用内的任务和策略工具，帮助把自然语言变成结构化记录。

设置模型→Agent 对话→任务草稿 / 进展摘要 / 策略 Skill
对话创建任务描述客户、工况、目标和约束，并明确说“创建任务草稿”。Agent 会先检查已有任务与优化策略，再保存 DRAFT；对话上传的最近一批附件可随任务归档。
对话跟进任务说“查看这个任务的状态、最近运行、温度和审批进展”。Agent 可读取任务、Run、Attempt、事件和 Artifact，生成进展摘要。
对话沉淀建议型 Skill明确说“把这条优化经验创建为策略 Skill”或“更新已有策略”。Agent 可检查现有策略后创建或版本化修改建议型优化 Skill。
证据型流程 Skill已完成任务的可执行流程草稿仍从任务页按证据生成，并在技能页人工审核启用；当前 Agent 对话不直接发布此类 Skill。
  1. 建单示例：“为 CTRL-100 创建散热任务草稿：环境 35 °C、持续负载 80 W，目标最高 85 °C，关注主芯片壳温，外壳尺寸不变。请先检查重复任务并说明推荐策略。”
  2. 跟进示例：“查看刚才创建的任务，汇总当前执行状态、最新 Attempt、温度证据、未解决问题和下一步。”
  3. 策略沉淀示例：“基于这次已确认的经验，新增一个建议型导热策略 Skill；先检查是否已有相似策略，没有实测降温数据就标记待验证。”
执行边界：对话可自动保存任务草稿、读取并总结进展、创建或更新建议型策略 Skill；任务确认、参数方案验证与执行、真实求解和证据型 Skill 发布仍需在 App 中人工操作。
03

核对或填写散热需求

Agent 建立的草稿可在此载入，也可直接手工新建。核对任务名称、工况、热目标和不可改动的边界；字段会进入任务详情，供专家复核。

  1. 点击“新建任务”。载入 Agent 草稿，或填写任务名称、客户与项目、产品型号、工况、详细需求。
  2. 填写目标与约束。Icepak 求解前必须有最高温度目标；关键监测点、允许调整范围和专家补充建议用于界定方案。
  3. 核对 AEDT 版本。上传 .aedt 前，将版本改为与本机安装一致的值。
04

上传模型并检查能力

可上传一个 .aedt 工程，或先上传 STEP、IGES、Parasolid、ACIS 中性 CAD 文件。点击“上传并检查模型能力”后查看结果。

输入检查结果与下一步
CAD 几何归档为待建模需求草稿。需先建立包含材料、热源、边界、监测点和 Setup 的 Icepak 工程，再回到草稿上传 .aedt。
.aedt 工程检查设计和 Setup，导出只读参数清单；曲线型原生风扇会额外执行不求解的写入／读回验证。只有检查通过才能进入 Baseline。
参数清单的含义：.aedt 检查可列出变量、材料、边界、风扇和 Setup；“发现”不等于“已验证可修改”。已验证风扇可在建单时单独预授权自动候选；完成 Baseline 后，还可在“参数修改与追溯”中编辑受支持的变量、材料、热源功率和指定风扇，并保存验证每一版方案。
05

分析候选方案并人工选择

“分析适合的优化方案”按需求关键词给出初筛建议。选择范围前，先核对模型能力状态和诊断依据。

  1. 点击“分析适合的优化方案”，阅读命中依据及每条策略的能力标记。
  2. 对 .aedt 任务，勾选本次纳入的方案，并确认需求、模型能力与方案范围；不选策略也可先做 Baseline。
  3. 只有已验证的风扇动作，才可单独授权“Baseline FAIL 后自动尝试所列全部风扇 +10%”一次。此自动流程与手动结构候选共用一次 Candidate 额度；希望自行比较参数版本时，可先只运行 Baseline。需要启动求解时，再选“提交后立即启动”。
06

回到任务详情跟进

任务列表显示模型、执行状态、热判定和审批。完成 Baseline 后，详情页顶部的“参数修改与追溯”可编辑参数、查看历史版本；侧栏“调整参数方案”也会跳到此处。进入详情后集中查看需求、求解证据与推进记录；也可直接让 Agent 读取任务并用对话总结最新进展。

专家记录可在“任务推进记录”署名补充建议；记录本身不会自动改模或启动求解。
状态不要混淆执行状态、热判定和人工审批分别显示；求解成功不等于温度达标。
07

Windows AEDT：运行与复核

以下步骤需要在已安装兼容 AEDT、PyAEDT 且可使用求解许可证的 Windows 机器上执行。本机 Mac 演示未运行真实求解。

  1. 进入“设置 → Icepak 插件”，完成 AEDT/PyAEDT 识别、独立会话启动验证和内置示例工程检查。示例检查不运行求解。
  2. 在任务表单上传客户 .aedt，运行模型能力检查；确认版本、设计、Setup、目标风扇及参数清单。
  3. 选择优化方案并确认需求。可立即启动本机 Baseline，或创建任务后在详情页启动。真实运行会占用求解许可证。
  4. 在任务详情核对最高温度、监测点、收敛结果和 Artifact 证据。若 Baseline 为 FAIL 且尚未执行结构候选，可进入“参数修改与追溯”生成并验证方案，再启动候选求解。完成后人工接受或拒绝；接受且证据齐全时可生成 PDF 报告，并按需沉淀 Skill 草稿。
运行边界：CAD 几何无法直接求解；关键词推荐不是物理诊断；预授权风扇与手动参数方案的结构候选合计最多执行一次；方案可以保存和验证多版。报告是审计证据归档，不是工程签字。
08

在 Task 中编辑参数

完成一次具有收敛证据的 Baseline 后，打开任务详情顶部的“参数修改与追溯”。每版方案都以此 Baseline 为起点，先验证修改，再决定是否求解。

Baseline 已收敛→搜索并添加参数→填写目标值与原因→保存新版本并验证
新配图的数据说明：图 9–14 来自当前 App 的隔离演示环境。参数、验证状态和温度由演示程序提供，仅说明操作与追溯方式，不是 Windows Icepak 的真实工程验证或降温结论。
可编辑类型如何填写需要满足的条件
已有模型变量例如 2mm → 1.5mm，保留单位；按实际含义确认结构或工况用途。变量已被模型引用、非只读、当前为数值常量。几何必须已有驱动变量，不会自动参数化 CAD。
对象材料选中实体对象，从下拉框选择材料。目标材料需已加载到工程；可选项排除已识别的气液材料。重量、成本等约束需人工复核。
热源功率例如 20W → 15W，保持当前功率单位。支持总功率热源；此类修改属于工况，会建立独立任务。
指定曲线风扇填写转速比，例如 1.1 表示 +10%。支持原生曲线型风扇，比例大于 1 且不超过 1.5；只调整选中的风扇。
  1. 确认基准并选择参数。检查上方基准记录、Design、Setup 和最高温度。旧任务没有可编辑清单时，点击“重新读取参数”，从原 Baseline 的工程副本补充清单，无需重新求解。
  2. 逐项查看“原值 → 目标值”。搜索名称或类型，选择参数后点击“添加”。数值输入保留单位；材料使用下拉选择；误加的行可点击删除图标移除。
  3. 确认用途和任务约束。厚度、间距等可属于结构设计；功耗、环境温度、入口条件属于工况。未分类变量必须按模型实际作用选择用途，不能仅依据变量名称猜测。
  4. 填写记录人与修改原因。写清诊断依据、预期作用及约束。点击“保存新版本并验证”后，形成独立的 v1、v2 等记录；这一步不会启动求解。
草稿与已提交版本“未提交 · 本机暂存”只保存在当前浏览器或桌面环境。保存成功后的版本进入任务历史，重新打开任务或重启 App 后仍可查看。
没有找到想修改的参数先重新读取清单；如果仍没有，请检查变量是否已引用、是否只读或派生表达式，以及材料是否已加载。当前版本不开放任意边界属性和未参数化几何修改。
09

比较版本，追溯验证与结果

“修改版本与执行结果”保存每次提交的原因、记录人、时间和状态。展开版本即可核对参数变化，历史方案通过“复制为新版本”继续编辑，不会覆盖原记录。

  1. 等待验证结束。“验证中”表示正在工程副本上写入并保存重开；“已验证 · 待执行”表示所选值已被重新读取确认，尚未求解。
  2. 比较两版内容。展开一个版本，在“与其他版本比较”选择另一版，按参数逐项查看差异。两版均从各自记录的 Baseline 出发，复制方案不代表在上一版工程上累加修改。
  3. 执行选定版本。确认目标值与原因后，点击“执行 vN 候选求解”。系统使用该版已验证工程；同一任务最多执行一次结构候选，需要 Baseline 为 FAIL 且尚未执行 Candidate。
  4. 分别核对修改、求解与热判定。“保存后验证”确认参数是否写入；求解状态确认运行是否完成；收敛与温度对比用于复核效果；最终接受结果仍需人工操作。
看到的状态含义下一步
验证中正在副本上执行写入、保存和重开验证。等待版本状态更新；可以离开页面后再回来。
已验证 · 待执行参数持久化验证通过，尚未启动求解。对比方案后执行，或复制为新版本修改。
已提交求解已创建关联运行，不代表求解完成或温度达标。继续查看下方求解状态、最高温度、收敛和温差。
失败 / 求解 FAILED验证、启动或求解某一阶段失败，错误记录保留。验证失败：查看错误并复制为新版本；求解失败：在对应任务的侧栏重试最近 Run，复用已验证工程。
复核时保存什么展开“基准、工程与证据标识”，核对基准记录、Design / Setup、工程 SHA256 和运行 ID；按需下载验证工程、验证证据及追溯 JSON。
失败不会抹去修改依据求解失败后，之前成功的参数验证仍可查看；重试继续关联同一个 Run。应用重启中断的验证或启动会明确留痕。
10

工况改变时，建立关联新任务

降低功耗、改变环境温度等会改变仿真条件。只要方案中包含工况变更，执行入口就变为“创建并求解 vN 新工况”，建立独立 Baseline，保留来源任务。

  1. 添加工况参数。例如选择热源 CPU，将总功率从 20W 改为 15W。功率会标记为“工况条件”；在修改原因中说明测试目的。
  2. 保存并验证。流程与结构参数相同，但用途提示会明确说明创建关联新工况。混合结构与工况修改的方案也走独立 Baseline。
  3. 创建并求解新任务。验证通过后点击对应按钮；来源版本中出现“打开工况任务”，可查看新任务的运行与审批状态。
  4. 回查来源。新任务顶部显示“此任务为独立工况基准”，点击“查看来源任务与修改记录”即可回到原任务。
如何解读结果：结构候选在同一 Baseline 下对比；新工况有自己的 Baseline 和目标判定，不把降低功耗得到的降温算作结构优化收益。每版方案的基准身份都可在追溯记录中查看。
11

技能库与计算节点

技能库用于查看和维护优化策略；明确要求 Agent 后，也可通过对话新增或版本化修改建议型策略 Skill。计算节点用于身份登记和受控远程执行；单机使用无需配置节点。

12

设置与 Agent 对话

设置页管理界面状态、App 工作空间、局域网发布和 Icepak 插件。Agent 用于对话整理需求草稿；最终建单与求解仍需人工回到任务页面核对。
